# Decisions

One line each: the decision, then the reason.

- 2026-11-24: The app is called Gom ("to gather"). A plain Vietnamese word, short, usable as a repo name and a subdomain.
- 2026-11-24: ASP.NET Core 10 with raw WebSockets, not SignalR. Learning the protocol is part of the goal; same stack as Peekbox.
- 2026-11-24: Separate service and repository from the shops, with its own accounts. The shops only send signed HTTP calls and plain links.
- 2026-11-24: PostgreSQL 19, its own instance, EF Core 10 with Npgsql. Peekbox staging already runs 19; CI tests 19 from the first commit.
- 2026-11-24: Messages are an ordered event stream per conversation (created, deleted; edits and reactions later), with a materialized messages table. Order comes from a per-conversation counter row, not a global sequence, so commit order cannot differ from sequence order.
- 2026-11-24: Browser code is framework-free TypeScript with lit-html, multi-page, as in Bloomy.
- 2026-11-24: Cookie is `__Host-` prefixed, `SameSite=Lax`, with an Origin check on every state-changing request. Lax because Strict drops the cookie on a link opened from another site (tested in Chromium); sibling subdomains of one registrable domain are same-site either way.
- 2026-11-24: Images, file uploads and Web Push are in version 1; uploads stay on our own disk behind a storage interface and are re-encoded server-side to strip location data.
- 2026-11-24: Target is 1,000 to 5,000 concurrent connections on one node, kept as a learning challenge (real use is under 100 people). No multi-node and no high availability for now. The load test is the last milestone.
- 2026-11-24: Backups are encrypted, cover the database and the uploads together, and are restore-tested by a script.
- 2026-11-24: Shop alerts carry no customer details, and only staff-only "ops" rooms receive them.
- 2026-11-24: This repository is public. No secrets, hostnames or home-lab details in any commit.
- 2026-11-24: MIT licence, the same as Peekbox and Bloomy.
- 2026-11-24: Friends are added by exact Gom ID, a link or a QR code, as a request the other person accepts; signing up through an invite makes you friends with the inviter. No phone-number lookup in version 1: it needs verified numbers (an SMS provider), stores personal data, and lets people find out who is on Gom.
- 2026-11-24: Only the owner invites, with a single-use link that expires; an invite can also put the new member in a group. Invite-only stays true because nobody else can open the door.
- 2026-11-24: Any member can create a group and add their own friends; members who are not friends need a friend request before a one-to-one message. Group links, avatar images and profile customization come after version 1 (a group link would let people in without an invite).
- 2026-11-24: Read receipts are in version 1 as one read position per member per conversation (`last_read_seq`), with an opt-out that hides yours and theirs; typing indicators and online status are not in version 1 (they would live in memory only). A position is one write however many messages it covers, and the other two need no storage.
- 2026-11-24: Ops rooms show in a staff member's list, are muted for push by default and are read-only (the shop posts alerts as a bot). Staff talk elsewhere; one rule for the room is simpler than two.
- 2026-11-24: A message sent while the connection is down waits and goes out when it returns; a failed send is retried with the same `client_id`, so a retry cannot duplicate it.
- 2026-11-24: Recall ("thu hồi") replaces a message with a placeholder for everyone, with no time limit in version 1.
- 2026-11-24: The look is Peekbox's sage and cream in Be Vietnam Pro, with avatars and sender names neutral so the colour stays one hue; light and dark follow the system and can be toggled. Mockups, tokens and notes are in `design/`.
- 2026-11-24: Sign-in is Gom ID plus password in version 1; passkeys may come later as an extra method. Relatives on old phones need something that works everywhere. .NET's built-in passkeys are scoped to full ASP.NET Core Identity, so adding them later means Identity or a WebAuthn library.
- 2026-11-24: Our own `users` table with `PasswordHasher<T>` (PBKDF2, iteration count set to 600,000 following OWASP; the .NET default is 100,000), not full Identity. We do not use its roles, email columns or UI.
- 2026-11-24: Sessions are server-side: the cookie holds a random token and the database stores only its hash. This allows sign-out per device, revocation, and a re-check on the WebSocket upgrade. A person can see and end their own other sessions.
- 2026-11-24: Only the owner resets a password, with a single-use link built like an invite. There is no email or phone in version 1, so nothing else could prove who is asking.
- 2026-11-24: Passwords are at least 10 characters with no composition rules, spaces allowed, at most about 128, and the most common ones are rejected. Sign-in attempts are slowed per Gom ID and per IP, never hard-locked, and a missing ID is hashed anyway so timing does not reveal it.
- 2026-11-24: A Gom ID is lowercase letters, digits and underscore, 3 to 20 characters, unique ignoring case, with reserved words blocked, and cannot be changed in version 1. A separate display name (a nickname, as in Zalo) defaults to the Gom ID.
- 2026-11-24: An invite lasts 7 days, is single-use, and the owner can revoke it at any time. Invites travel through other chat apps, so 48 hours would be too short.
- 2026-11-24: The owner account is created at first start from `Owner__GomId` and `Owner__Password` when the users table is empty, then the password is removed from the configuration. No web page and no command, so nobody can race the owner to it. Losing the owner password later means a database edit by the host's operator.
- 2026-11-24: Signing up through an invite signs the new member in. A reset link lasts 24 hours, only one is live per person, and using it ends all that person's other sessions and signs them in.
- 2026-11-24: The browser code is bundled with esbuild into one `wwwroot/js/main.js`, type-checked with `tsc` and tested with vitest and jsdom (Peekbox's checks). Plain `tsc` output cannot resolve `import 'lit-html'` in a browser without an import map or a copy out of `node_modules`; one bundle for all pages is the smallest fix.
- 2026-11-24: Every response carries a strict Content-Security-Policy (own script and styles only, no inline, never framed); pages and API answers are never cached, and no page sends a Referer, because an invite or reset link carries its token in the address. So pages hold no inline script or style; the colour scheme is set by a blocking `theme-init.js` before the styles load.
- 2026-11-24: A member changes their own nickname and password in settings. A new password needs the current one, is slowed like sign-in (a stolen session must not be a free way to guess), and signs out the other devices but not this one.
- 2026-11-24: The owner can lock and unlock a member. Locking ends all their sessions and blocks sign-in; nothing of theirs is deleted. The owner cannot be locked. This is the only "remove a member" in version 1, because deleting would orphan their messages.
- 2026-11-24: A friendship is one row per pair, stored in a fixed order (the smaller id first), so "A asks B" and "B asks A" cannot be two rows. Asking someone who already asked you makes you friends at once. A declined or cancelled request leaves no trace, and can be made again.
- 2026-11-24: Blocking ends any friendship or request between two people. The blocked person's friend request looks as if it went out but is not stored, so they cannot tell. You cannot ask someone you blocked until you unblock them. Locked members drop out of every friend list.
- 2026-11-24: A one-to-one conversation can be started only between friends, and a pair has one (unique key `low:high`). Once it exists it stays in both lists after an unfriend or a block so the history is not lost; sending is a separate rule, decided with messages.
- 2026-11-24: A friend link is `/add/{gomId}`: opened signed in it shows a button, and nothing is sent until it is pressed (a link must never change anything); signed out it goes to sign-in and comes back (`?next=`, only a path on this site). A QR code is not built yet: it would only be a picture of this link.
- 2026-11-24: A message is up to 4,000 characters as a person counts them (an accented letter or an emoji is one), with a hard stop at 16,000 code units so a run of combining marks cannot be a way around it. Line breaks and tabs are kept, other control characters are refused, the ends are trimmed, an empty message is refused.
- 2026-11-24: A send is `POST /api/conversations/{id}/messages` with a `clientId`. The first send with that pair (sender, clientId) wins: a retry gets the stored message back whatever the text now says and even after an unfriend, and costs no sending allowance. A `clientId` cannot be reused in another conversation (409). The sequence number comes from the conversation's counter row, bumped in the same transaction that stores the message and its event, so numbers follow commit order; a copy that loses a race is rolled back, counter included.
- 2026-11-24: Sending is slowed per person with a token bucket: a burst of 20, then 2 a second, in memory (`Chat:SendBurst`, `Chat:SendPerSecond`). A real family does not hit it; a stuck client or a stolen session does.
- 2026-11-24: History is paged by sequence number, not time: "the 50 before seq N" (at most 100). Opening a conversation never needs a clock.
- 2026-11-24: Your own message is never unread: sending moves your read position to it. The list shows the start of the last message (200 characters), the unread count (others' messages after your position), and puts the newest conversation first.
- 2026-11-24: Live delivery is one WebSocket at `/ws`, server to client only: the server pushes `event` frames, a device asks for what it missed with `{"t":"sync","c":<conversation>,"after":<seq>}` and gets up to 200 events a page with `hasMore`. Sending stays on REST, so a send is one request with one answer whether or not a socket is open.
- 2026-11-24: Each socket has one bounded queue (64 frames) and one writer loop. Whoever has news only queues it and never waits. A client that falls behind, or whose frame takes more than 10 seconds to leave, is closed with 1013 and catches up from its cursor. Delivery runs after the commit and cannot fail a send.
- 2026-11-24: The upgrade needs a live session and one of our own origins (an upgrade is a GET, but it opens a long channel with the cookie). Membership is read at the moment of delivery and again on every sync. A person may hold 5 sockets; the oldest is closed (1008) to make room. Close code 4401 means "your session ended": sign-out, ending a session from settings, a password change (other devices), a reset, or a lock all close the sockets at once.
- 2026-11-24: The list and the thread are one page for `/` and `/c/{id}`; opening a conversation changes the address without a reload. On a wide screen both show (340 px list, thread beside it); on a phone one at a time, and the browser's back button returns to the list. A row is a real link, so a new tab still works.
- 2026-11-24: In the composer Enter sends on a keyboard and Shift+Enter makes a new line; on a phone (coarse pointer) Enter makes a new line and the button sends. A word still being composed (Vietnamese Telex, VNI) is never cut off by Enter.
- 2026-11-24: A device that gets close code 4401 goes to sign-in; one that gets 1008 (another window took its place) stops and says so, because two windows would otherwise evict each other forever. Any other close reconnects after 1 s, 2 s, 4 s ... up to 30 s with a random share taken off, and on reconnect the list is reloaded and the open thread is caught up from its newest sequence number.
- 2026-11-24: Messages go out one at a time per conversation, in the order written. A bad network is waited out for ever (retry when the socket returns, when the browser says it is online, when the page is shown, and on a timer of 1 s, 2 s, 4 s ... up to 30 s); a busy server (5xx) or "slow down" (429, which names its own wait) is tried 5 times, then the message is called failed. A message the server refuses for good is failed at once with the reason, and does not hold back the ones behind it.
- 2026-11-24: Messages not yet delivered are kept in the browser's local storage (per person, removed the moment they are sent) so a phone that discards a background tab does not lose them. After a reload they are sent again with the same ids, which is harmless because a send is idempotent. The cost: until it is sent, the text sits unencrypted in that browser's storage.
- 2026-11-24: A message's sender is `{id, displayName}`, never a Gom ID. A Gom ID is shown to the person themself and to their friends only, so members of a group who are not friends see names, not IDs (design rule 3). The member list says `gomId` only for you and your friends.
- 2026-11-24: Any member makes a group from their own friends (a name of 1 to 60 characters, at least one other person, at most 50 in all, `Chat:MaxGroupMembers`) and any member adds more of their own friends. A stranger, an unknown ID and a locked member all get the same `not_friends`. Nobody can remove another member in version 1; a member can leave, and a one-to-one chat cannot be left.
- 2026-11-24: A new member of a group sees only what is said after they join (`joined_seq`), in history, sync, the list preview and the unread count. This is the cautious default for a family chat: adding someone must not hand them years of earlier conversation. The other choice (everything) is one condition to remove.
- 2026-11-24: Another member of a group can be asked to be friends from inside the group by their opaque id, without ever seeing their Gom ID, and only if you share that group. It follows the same rules as asking by ID (blocks, already friends, a blocked asker cannot tell). When a group is made, someone is added or someone leaves, every member's devices are told to reload their list (`{"t":"conversations"}`).
- 2026-11-24: In a group thread the speaker's name shows above the first message of a run and their initials beside the last, never for your own messages and never in a one-to-one chat. Leaving a group asks twice. The group page lists only your own friends to add, and a member who is not your friend shows a "Kết bạn" button instead of an ID.
- 2026-11-24: Taking a message back ("thu hồi") erases its words in the database and takes the next sequence number as a `deleted` event, so every device, including one that was away, learns of it from the same stream it uses for new messages. Only the sender can, with no time limit; doing it twice changes nothing; it still works after an unfriend but not after leaving a group. Everyone then sees a dashed placeholder where it was ("Bạn đã thu hồi một tin nhắn", "Tin nhắn đã được thu hồi", or "Minh đã thu hồi một tin nhắn" in a group).
- 2026-11-24: A device's cursor is the last step of the stream it knows of (the history answer carries `lastSeq`), not the newest message: a recall takes a number but adds no message, so counting messages would make every recall look like a gap. A member who joined after a message was written is not told it was taken back.
- 2026-11-24: Read receipts use the per-member read position that already drives the unread count, with one switch per person (`users.share_read_receipts`, on by default, in settings) that works both ways: hide yours and nobody sees it, and you see nobody's. The position is always kept; the switch decides only who may be shown it. Sending a message moves your own position, so it tells the others too.
- 2026-11-24: The thread shows "Đã xem" under your last message in a one-to-one chat, and "Đã xem bởi n" in a group, once someone who shares has read up to it. `GET /api/conversations/{id}/reads` gives the positions; a `read` frame is pushed only when a position actually moves, only to members who share, and never to the reader.
- 2026-11-24: CodeQL runs from `.github/workflows/codeql.yml` (the action pinned by commit) and skips `design/source`: the mockup boards fill their frames with `innerHTML` from literals in the same file, are not served, and raised 9 high alerts. The repository's default setup is switched off once this is merged, or every alert would be reported twice.
- 2026-11-24: A group has a leader (its creator) and deputies the leader names. Leader and deputies remove members; a deputy cannot remove the leader or another deputy; only the leader names deputies, hands leadership over, or disbands. The leader must hand over before leaving. A removed member keeps the old messages and cannot send, as after an unfriend, and can be added again. Join approval and a block from rejoining come later.
- 2026-11-24: Unsent messages stay in the browser's local storage until sent (and are cleared on sign-out); a new group member sees only what is said after joining; unfriend and block ask first; the QR code waits. The message menu is a hover button on desktop and a long press on a phone (reply, copy, forward, recall).
- 2026-11-24: Added, in order, as small pull requests: reply, copy, mute, group rename, delete for me, first-unread divider, search in one conversation, then images and files, pin, reactions, forward, edit, join approval, web push, and last typing and online status, voice and polls. Each is a design-notes rule before it is code.
- 2026-11-24: `docs/repo-review.md` is the prompt for a whole-repository review, run before each milestone ends and before the first deployment, so each run checks the same things the same way (modelled on Peekbox's).
- 2026-11-24: First repo review fixes: EF statements are not logged in any environment (`Database.Command` at Warning); `HEAD` is answered on pages and `/healthz` so a monitor does not read 405 as down; no `Server` header; `Permissions-Policy` denies camera, microphone and location (voice messages will open the microphone); scripts and styles are revalidated by ETag on every use until they are fingerprinted, fonts are kept a week; a socket that sends 5 unreadable frames is closed (1008). Asking for a conversation that is not yours is not counted as unreadable.
- 2026-11-24: Gom ships as one image built from the `Dockerfile` (the site, and the migration bundle at `/app/efbundle`, run before each start), published to GHCR by `images.yml` from `main` only, tagged with the first 12 characters of the commit, never `latest`; base images are pinned by tag and digest. Behind a proxy chain `ForwardedHeaders:Hops` says how many proxies to believe (0 by default; staging is 2). Nothing in Gom uses the data-protection keys, so the container needs no volume until uploads arrive.
- 2026-11-24: This corrects the group-role line above: a removed member keeps nothing, exactly as after leaving (their member row is deleted, so the group leaves their list and they cannot read or send), because the first line promised more than the code gives and keeping history for someone who is out of a group matters more than in a one-to-one chat. Someone added again sees only what comes after. Disbanding deletes the group and its messages for everyone. Handing over makes the old leader a plain member. A leader alone in a group who leaves ends it. Rename by leader and deputies comes with the rename slice.
- 2026-11-24: Answering a message (`messages.reply_to_id`, same conversation, a message you can see and that is not taken back; refused with `invalid_reply` otherwise). An answer carries a small quote (who wrote it and its first 100 characters, by text elements so an emoji is never cut). A reader who joined after the quoted message, or a quoted message taken back, shows "Tin nhắn không còn hiển thị": the live frame for such readers is built separately, so their devices never receive the words. Taking back an answer removes its quote. The "⋮" button is on every arrived message and opens Trả lời, Sao chép and (your own) Thu hồi; the hover and long-press forms stay to do.
- 2026-11-24: Forwarding passes the words of a message to another conversation as a new message from the forwarder, with no answer and no mention of who first wrote it (nothing to leak, nothing to keep in step). It uses the writing queue, so a lost connection does not lose it; a refusal for good is told to the forwarder and leaves nothing behind in the other conversation. No server change.
- 2026-11-24: A person can mute a conversation (`conversation_members.muted`, theirs alone; `PUT /api/conversations/{id}/mute`). It keeps its unread count and its place in the list, shows a crossed bell and a grey badge, and their other devices reload the list. It is the switch push notifications will read later; nothing else changes yet.
- 2026-11-24: A group's name can be changed by its leader and its deputies (`PATCH /api/conversations/{id}`, the same rules as at creation: 1 to 60 characters, no control characters). Everyone in the group reloads their list. Roles are read again under the group's lock, so someone demoted at the same moment cannot rename. A notice in the thread saying who renamed it waits for the thread notices.
- 2026-11-24: "Delete for me" (`PUT /api/conversations/{id}/messages/{messageId}/hidden`, table `message_hides`): one person stops seeing a message (theirs or another's, taken back or not) in history, sync, the list preview and unread count, and a quote of it shows nothing of its words; everyone else is unaffected. Doing it twice changes nothing, and only what the person can see can be hidden (anything else is a 404). Their other devices drop it at once (a `hidden` frame to them alone). Ending a group removes the hides with the messages. Searching will skip hidden messages too.
- 2026-11-24: Opening a conversation with unread messages scrolls to the "n tin nhắn mới" divider (once; if the first unread message is further back than what was loaded, it starts at the end), and a message from someone else that arrives while you are reading further up shows a "n tin mới" button that takes you down. Browser only.
- 2026-11-24: Search in one conversation (`GET /api/conversations/{id}/search?q=`, 1 to 100 characters, at most 30 results, newest first) ignores capitals and accents ("pho" finds "Phở", "dinh" finds "Đình") using PostgreSQL's `unaccent` extension (migration `SearchUnaccent`; checked on staging, where the app's role is a superuser and the extension is available). `%`, `_` and `\` typed by a person are ordinary characters. It finds only what the person can see: after they joined, not taken back, not deleted for themself. It reads the conversation's own messages with no search index (fine at this size; a trigram index is the first thing to add if a chat grows large). Tapping a result loads older pages until the message is there and marks it for a moment.
- 2026-11-24: A socket is sent a small JSON heartbeat every 25 s (`Chat:HeartbeatSeconds`), which any idle timer in the path sees as data (the WebSocket layer's own 25 s signal is an unsolicited protocol PONG that the page cannot see and a proxy may not count). The page treats 60 s without any frame as a dead connection even when the browser still calls it open, lets go of it and reconnects at once, and checks the same (35 s) when the tab is shown or the network returns; before this a silently dropped connection was never noticed. Every socket close is logged at information level with who ended it (client, server with its own fixed reason, or the line was lost), the code and the age in seconds; what a client writes as its close reason is never logged.
- 2026-11-24: Any member of a conversation may pin a message for everyone in it, and unpin it; at most 3 (`Chat:MaxPins`, a fourth is refused with 409 `pin_limit`, counted under the conversation's lock so two at once cannot pass it). The newest pin shows under the header, with a list of all when there are several. Someone who joined later, or who deleted the message for themself, is not shown a pin of it; a message taken back is unpinned; ending a group removes its pins. Everyone in the conversation is told to ask again when the pins change.
- 2026-11-24: Reactions: one of six emoji (👍 ❤️ 😆 😮 😢 😡) per person per message, chosen again to change and taken back to remove (`PUT/DELETE /api/conversations/{id}/messages/{messageId}/reaction`, table `message_reactions`). A change takes the next number of the conversation as an `updated` event (a new kind beside created and deleted, allowed by the event table's check), so a device that was away learns of it from the stream; choosing what you already chose, or taking back what is not there, takes no number. Only people still in the conversation are shown, with their names and opaque ids; reactions of a message taken back are not shown; nobody is told of changes to a message they deleted for themself (this also fixes a taken-back message reappearing as a placeholder for someone who had deleted it). A device ignores an `updated` event for a message it never loaded, so paging stays right.
- 2026-11-24: A person can change the words of their own message (`PATCH /api/conversations/{id}/messages/{messageId}`, with no time limit, as with taking back; the old words are not kept; `messages.edited_at`). It takes the next number as an `updated` event, so everyone is told live and a device that was away gets the new words; the message shows "đã chỉnh sửa". Only the sender, only a message that is still there and in that conversation, with the same checks and limit as writing a new one; writing the same words again changes nothing. Quotes, pins and search read the new words; forwarded copies and quotes already on a device's screen are not changed until it next loads.
- 2026-11-24: The message menu opens by right-click (or the context-menu key) on a message, by holding a finger on it for 450 ms (not if the finger moves more than 10 px, which is scrolling, and not for a mouse), or with the ⋮ button, which stays in the page for keyboards and screen readers: it is drawn only on hover or focus with a mouse, and not drawn (but still reachable) on a touch screen. This replaces the "⋮ is a stand-in" line. Browser only; how it looks and feels on a real phone or in Safari is not verified.
- 2026-11-24: A group can ask for approval before people are added (`conversations.join_approval`, set by the leader with `PUT /api/conversations/{id}/settings`). With it on, a plain member who adds a friend only asks (202, a row in `join_requests`); the leader and deputies add directly, see the requests by name (never a Gom ID) and who asked, and approve (the person is in, seeing only what comes after) or decline; the member who asked may take their own request back. Turning it off drops what was waiting. Removing someone can also ban them (`DELETE .../members/{id}?ban=true`, table `group_bans`): nobody can add them, and no request for them can be approved, until the leader lifts the ban; leaving is never a ban. The leader and deputies are told to reload when a request arrives. Ending a group removes its requests and bans.
- 2026-11-24: The message menu is a floating layer, not a panel in the thread: a small list with icons beside the pointer for a mouse (opened by the button beside the bubble, which also has a reply button, shown only on hover or focus, or by right-click), and a sheet at the bottom with the reaction row and a grid of actions for a finger (opened by a long press; no visible button on a touch screen). Opening it never moves the messages; the dimmed area behind it and Escape close it. Its place is set with `style.setProperty` after drawing, because the page's content security policy refuses an inline style attribute (a test scans the scripts for one).
- 2026-11-24: In a thread, messages from one person within five minutes sit 2 px apart and a new run gets 10 px; the time shows on the last message of a run (and on one still being sent or edited), and the others keep it as a tooltip and for screen readers.
- 2026-11-24: Friends and groups are one page, "Danh bạ" (still at `/friends`): the add-friend form and your link inside a closed box, requests on top, then two tabs (Bạn bè, Nhóm) with a search field and a handful (5) of rows before "Xem thêm"; a search looks through every row. The header of the list has the Gom button (home), the theme toggle, contacts and settings; the pen is gone, "Nhóm mới" is on the Groups tab. Unfriend and block sit behind a "more" button on each friend. The list of conversations and the group picker have a search that ignores accents and capitals (`Scripts/search.ts`). The empty right side shows a welcome.
- 2026-11-24: Settings is grouped in sections (a profile card with your avatar, Hồ sơ, Giao diện, Quyền riêng tư, Bảo mật, devices) and the colour scheme moved there from the list header, as a three-way choice (follow the system, light, dark; `Scripts/theme.ts`). Avatars get one of six colours from the person's name (`avatarTone`), so people are easy to tell apart without storing anything; a chosen colour or a photo comes with M3 images.
- 2026-11-24: M3 pictures and files, step one (storage and upload; putting them in messages and the browser come in the next steps). A picture or file is uploaded on its own (`POST /api/conversations/{id}/attachments?name=`, the raw bytes as the body) and later referenced by a message; until then only its uploader can fetch it, and unused uploads are deleted after an hour (`Uploads:PendingHours`). A picture (JPEG, PNG or WebP, recognised by its first bytes, not by what the sender calls it) is decoded, turned upright by its metadata, scaled so its longer side is at most 1600 px, and stored as lossy WebP (quality 80) with a 400 px small version, so no location, camera or time data survives and a 4 MB phone photo is a few hundred KB (measured: 1.8 MB to 121 KB); the original is not kept. Anything else is a file, stored as it is and only ever served as a download (`application/octet-stream`, `attachment`, `nosniff`), under a cleaned name (no path, no control or direction-changing characters, 120 letters). Limits, all in `Uploads:*`: pictures 10 MB, files 25 MB, 60 million pixels (judged from the header before decoding), a burst of 12 uploads then 1 per second per person, and as many pictures decoded at once as half the CPU cores. Files are not compressed: PDFs, Office files, archives and photos are already compressed. Bytes live on disk behind `IBlobStore` under `Uploads:Path` (empty means uploads are off, 503), named by random ids; the folder must be a persistent volume and part of the backup. Pictures may stay in the browser for a day (`private, max-age=86400`); everything else in `/api` stays `no-store`.

- 2026-11-24: Invites are reusable (H: owner only invites, but they only expire over time and can be revoked, not single use). One link works for several people until it expires (1, 7 or 30 days; 1 to 30 allowed), is revoked, or has let in as many as chosen (1, 10 or any number; 1 to 100 allowed); with no choice the defaults are 7 days and 10 people (`Auth:InviteDays`, `Auth:InviteMaxUses`).
